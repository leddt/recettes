## Cursor Cloud specific instructions

### Architecture

- **Frontend**: React 19 + Vite 7 + Tailwind CSS 4 + shadcn/ui (French-language UI)
- **Backend**: Convex (serverless BaaS — DB, auth, functions, file storage, search)
- **AI**: OpenAI API (recipe import, chat, embeddings)
- **Auth**: `@convex-dev/auth` with password provider

### Running the dev environment

1. Start both backend and frontend: `pnpm dev` (runs `convex dev --start vite`)
   - Convex local backend runs at `http://127.0.0.1:3210`
   - Vite frontend runs at `http://localhost:5173`
   - Convex dashboard at `http://127.0.0.1:6790/?d=anonymous-workspace`
2. On first setup, `convex dev` prompts interactively — select "Start without an account (run Convex locally)"
3. After Convex backend is running, configure auth: `npx @convex-dev/auth` (generates JWT keys)
4. Seed the default test account: `pnpm seed` (creates `famille@recettes.local` / `recettes123`)

### Gotchas

- After `pnpm install`, esbuild build scripts are ignored by default. Run `pnpm rebuild esbuild` to ensure the binary is available for Vite.
- The Convex local backend stores state in `~/.convex/anonymous-convex-backend-state/`. The `.env.local` file is auto-generated by `convex dev`.
- AI features (recipe import from URL/photo, AI chat, semantic search) require `OPENAI_API_KEY` set as a Convex env var: `npx convex env set OPENAI_API_KEY <key>`. Defaults: `gpt-5.4-mini` (import URL, chat); `gpt-4.1` (import photo); `text-embedding-3-small` (search). Optional overrides: `OPENAI_IMPORT_MODEL`, `OPENAI_VISION_MODEL`, `OPENAI_CHAT_MODEL`, `OPENAI_EMBEDDING_MODEL`.
- The app has no manual recipe creation UI — recipes are imported via URL or photo using AI extraction.

### Settings page (`/settings`)

- **Appearance**: theme selector (light / dark / system), persisted in the browser.
- **Push notifications**: shown only when `VITE_VAPID_PUBLIC_KEY` is set in `.env.local`. Each user enables notifications per device from this page.
- **Users**: account management (create, edit, change password, delete). Public sign-up is disabled; additional accounts are created from this UI after the first account exists.

### Push notifications setup

Generate VAPID keys and configure:

```bash
npx web-push generate-vapid-keys
npx convex env set VAPID_PUBLIC_KEY <publicKey>
npx convex env set VAPID_PRIVATE_KEY <privateKey>
npx convex env set VAPID_SUBJECT mailto:famille@recettes.local
```

Add to `.env.local`: `VITE_VAPID_PUBLIC_KEY=<same public key>`.

When a member imports a recipe, other subscribed members receive a native push (recipe cover image used when available). The importer does not receive their own notification.

Users can enable/disable per device or disable everywhere (all account subscriptions). UI shows device count with context-aware labels. Requires HTTPS in production; iOS requires PWA installed on home screen (iOS 16.4+).

Backend: `convex/pushSubscriptions.ts`, `convex/pushNotifications.ts`. Service worker handler: `public/service-worker/push.js`.
